When triage cannot assess an update, the board now tells you.

## Fixed

- **Failed runs show up on the board.** GitHub emails a failed workflow run only to whoever triggered it, so when a contributor's comment led to a run that failed or was left for a maintainer, nobody heard about it. The card's next step now says "Triage could not assess the latest update" with the reason, and a card waiting on others comes back to Do. By @crmne.
- **A bot comment can no longer cancel triage of a human one.** GitHub keeps one queued run per conversation and replaces it with the next. Because the README's workflow set this up for the whole workflow, a bot's comment, whose run is then skipped, could replace the queued run of a human comment just before it. The example now sets it on the job, which a skipped run never reaches. Update your workflow to match. By @crmne.

Verified with RuboCop and 311 specs, and against three days of runs across 46 repositories: since v0.10.1, no triage run has failed.
