Fewer failed assessments, and the ones that still fail say why. A token that expired on the board, a tool call the model garbled, and a line of Copilot output that was not JSON each failed runs across a whole account. This release stops the last two and names the first.

## Fixed

- **A failed board request names its cause.** Every failure used to read "GitHub project request failed.", whatever went wrong. It now gives GitHub's own message, so an expired `TRIAGE_PROJECT_TOKEN` reads as that instead of looking like a Copilot problem. It failed 37 of our runs before we could tell why. By @crmne.
- **Archived cards are left alone.** Closing an issue whose board card was already archived failed the run. Triage now skips the card. By @crmne.
- **A malformed tool call gets one more try.** When the model writes a tool call whose arguments are not JSON, the run starts over once with a fresh conversation, as it already does when a run ends without a decision. Truncated calls are not retried, since they would stop at the same limit. By @crmne, following the proposal in [#15](https://github.com/crmne/copilot-triage/issues/15) by @pch.
- **Copilot output that is not JSON no longer fails the run.** The decision comes from the tool ledger, so a stray line costs nothing. Spotifast [#1142](https://github.com/crmne/spotifast/issues/1142) failed on one. By @crmne.
- **Silent Copilot failures report their error.** When Copilot exits without writing to stderr, triage reads the error from its output instead of saying nothing useful. By @crmne.
- **RubyLLM 2.1.1.** The action and the preview workflow now install the same version the specs run on. By @crmne.

Verified with RuboCop, 501 specs, the 36-case offline reply evaluation, and the live reply evaluation on `gpt-5.6-luna` through Copilot, which passed 31 of 36. Reruns of the misses were mixed, so we ran three of them against v0.20.0's code on the same model: they passed 3 of 9 there and 4 of 9 here, and this release changes no prompts or evaluation cases. The misses are the model's, not new. The board, archived card, and malformed tool call changes were tested against recorded or stubbed responses, not tried end to end.

## Known limitations

- The Copilot error format is inferred from its logs and has not been seen on a real failed run. If it differs, a silent failure stays silent, as it does today.
- `new-long-report-summary` keeps missing the "90%" it wants in a recap, and `spotifast-1069-short-report-fixed-on-main` and `zapfast-631-recap-of-options-for-maintainer` each pass about one run in three.
