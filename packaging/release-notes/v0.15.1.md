The sweep no longer misreads pull requests right after a push to the base branch, and a failed run no longer moves cards.

## Fixed

- **Pull requests keep their column while GitHub is still checking them.** Right after a push to the base branch, GitHub briefly reports a pull request's mergeability as unknown. The sweep read that as mergeable, so conflicting contributor pull requests moved to Do and requested your review. Their cards now wait for the next sweep. By @crmne.
- **A failed run leaves the card where it is.** When triage could not assess an update, it moved the card to Do and wrote the raw error as the next step. It now keeps the column and says in plain words that triage could not assess the latest update. By @crmne.
- **Clearer next steps from the sweep.** Your own failing pull request says to fix its checks, a review bot's requested changes are named as such, and an issue that follows a pull request says which one. By @crmne.

Verified with RuboCop and 332 specs, and against a board audit after v0.15.0.
