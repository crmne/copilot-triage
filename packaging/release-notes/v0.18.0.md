Triage talks less and gets more right. We audited everything it did across our repositories in one week: labels were 95% right, but only a third of its replies helped. This release fixes what that audit found: replies nobody needed, question chains, wrong closures, unreviewed pull requests waiting for your sign-off, and conversation state that was never saved.

## New

- **Replies are for the reporter.** A reply that tells the maintainer what to decide, investigate, or prioritize is dropped; that goes in the card's next step. The initial recap is kept for long, unstructured reports, not issue-template reports that are already easy to read. By @crmne.
- **At most two replies in a row.** After two triage replies since a maintainer last commented, triage stops replying in that thread and moves the card to Decide, so nobody gets five questions in an hour. By @crmne.
- **No repeated links.** A related issue the conversation already mentions, one triage linked before, or the issue a pull request closes is not posted again, and the agent cannot cite the report itself. By @crmne.
- **Unreviewed pull requests stay out of Sign off.** A contributor's pull request reaches Sign off only after a bot or a person reviewed its latest commit; otherwise it waits in Do with "No review of the latest commit: read the change". This caught dozens of pull requests that CodeRabbit never reviewed after hitting its limit. By @crmne.
- **Contribution rules get checked.** Each pull request report lists the media files it adds, the dependency files it changes, and any new git or path dependency, so the agent can match them against your CONTRIBUTING.md and send the change back naming the rule. Pull request replies that review code line by line are refused. By @crmne.
- **Discussions are answered where they belong.** A request your documented scope rules out, or a maintainer already declined, is answered in the discussion instead of being moved to an issue only you can close, and a move no longer fails over citations, which the new issue's assessment finds for itself. A new question on a discussion closed as resolved gets a sourced answer. By @crmne.
- **Every file read says how far it is from the release.** Files the agent reads from the default branch carry a note such as "(default branch, 183 commits after v0.19.0)". By @crmne.
- **Quiet manual runs.** `assess.yml` takes a `quiet` input, so re-assessing a backlog sorts it onto the board without posting. By @crmne.

## Fixed

- **Conversation state is saved again.** GitHub made the cache read-only for issue and comment events, so every run forgot muted threads and its own earlier replies. The shared workflow now asks for cache writes. Callers that do not set `cache-mode` need no change; a job that calls the action directly needs `cache-mode: write`. By @crmne.
- **No more duplicate closures that hide a recurrence.** An issue closed as completed, or an error tracker's report that reopened, is linked as a recurrence instead of closing the new report as a duplicate, and a reporter's re-filed copy stays open. By @crmne.
- **"Resolved" only on the reporter's word.** A bystander retracting their own comment no longer produces a "Closing as resolved" reply. By @crmne.
- **Duplicates match the problem, not the title.** By @crmne.
- **No contradictory labels.** `bug` with `enhancement`, or a second type label on a report that already has one, is refused. A discussion that would be labeled `wontfix`, `out-of-scope`, or `invalid` stays a discussion. By @crmne.
- **Pull requests stop bouncing between columns.** The sweep no longer withdraws and re-requests your review on an unchanged commit, no longer sends a pull request back over CodeRabbit's change request on an older commit, and keeps a pull request in Their move while triage's question waits on its author. By @crmne.
- **Next steps are in English**, unreleased work you are implementing goes to Do, and waiting on upstream is never urgent Do work. By @crmne.
- **A repository without `.github/triage.yml` is skipped** with a notice instead of failing, which happened on every policy pull request before its file merged. By @crmne.
- **Fallback runs finish.** When the model stops without a decision, the reminder now forces the decision call, which fixes runs that ended with no decision on OpenRouter. By @crmne.
- **Replies can name a mention.** A reply about `@all` or a username failed the whole assessment; mentions now become inline code, which names them without pinging anyone. By @crmne.
- **Clearer failures.** An invalid assessment says which check rejected it, a failed GitHub call names the request and GitHub's reason, and board notes no longer fail on discussions. Em dashes in replies become commas. By @crmne.

Verified with RuboCop, 436 specs, the 32-case offline reply evaluation, and the live reply evaluation on `gpt-5.6-luna`, which passed 30 of 32 cases: the two misses found the right answer (an unreleased feature, a duplicate) but missed wording the cases require. Moving a real discussion and the cache write were not tried end to end; the first issue run after this release should show a saved `triage-v2-` cache.

## Known limitations

- The maintainer-directed filter matches words such as "maintainer", so a reply that needs to mention one is dropped unless it is about maintainer approval.
- Pull request replies that name a setting key like `show_queue` can be refused as code review; the agent is told to rephrase.
