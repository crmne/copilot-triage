The board's columns now say what each item needs from you: **Sign off**, **Decide**, **Do**, **Their move**, **Not now**, and **Done**. Triage also closes what is plainly finished on its own, with a comment that says why, and your own pull requests no longer cost a model call or ask you to review yourself.

## New

- **Columns named for what they ask of you.** Sign off: say yes to a prepared result, such as a pull request ready to merge or a closure triage proposes. Decide: feature requests, scope and design calls, answers only you can give. Do: a bug to fix, a pull request worth a close read, your own work. Their move: a contributor, reporter, reviewer, or upstream has the next step. Not now: accepted, but nobody acts until you choose. By @crmne.
- **Triage closes finished issues.** With `closing: auto`, an issue is closed after a short explanation when a published release fixed it (citing the release notes), when the reporter says it is resolved, or when your documented scope rules it out (citing the document). It never closes an issue a maintainer opened, joined, or reopened; those, and every closure under the default `closing: suggest`, wait in Sign off for your yes. By @crmne.
- **Your own pull requests skip the model.** Their checks, conflicts, and reviews place them on the board, so they cost nothing and nobody asks you to review your own work. By @crmne.
- **Review requests come from the workflow, not from you.** The sweep requests and withdraws your review with the repository's workflow token instead of your project token. By @crmne.
- **Other review bots count.** A decisive review from a bot such as CodeRabbit on the latest commit places a pull request like a human review: requested changes go back to the author, and an approval of a ready pull request goes to Sign off. By @crmne.
- **Issues follow their pull request.** An issue with an open pull request that would close it moves with that pull request's card, so the two finish together. By @crmne.
- **A failing default branch gets its own card.** While the default branch fails its checks, an urgent card in Do says so, because every pull request inherits the failure. It is archived once the branch passes. By @crmne.
- **Pick a repository beside the board.** Choose **Slice by** › **Repository** in the board view's menu for a list of repositories with their counts; one click filters the board. GitHub's API cannot set a slice, so the sweep no longer creates a view per repository. By @crmne.

## Fixed

- **The daily sweep works again.** Since v0.8.4, the sweep asked GitHub for the names of requested teams, which needs a scope the board token lacks, so it failed before moving any card. It now recognizes a team request by its type, and leaves your review request alone while a team's is pending. By @crmne.

## Changes for existing workflows

Workflows on `crmne/copilot-triage@v0` receive this release automatically.

- **The columns are renamed in place.** On the next sweep, Approve becomes Sign off, Answer or decide becomes Decide, Fix becomes Do, Waiting on others becomes Their move, and Backlog becomes Not now. Cards keep their places. Review is retired and its cards are placed again. If you named columns in `board.columns`, use the new keys: `sign_off`, `decide`, `do`, `theirs`, `not_now`.
- **The sweep needs two more permissions** to request reviews and send fork pull requests to triage: `pull-requests: write` and `actions: write`. See the README.
- **Closing is opt-in.** The default, `closing: suggest`, explains and proposes the closure without closing.

## Known limitations

- GitHub's API cannot set a view's sorting or grouping beyond the board's columns; sort a view by Priority in the project if you want it.
- Fine-grained tokens cannot reach user-owned projects yet, so the board needs a classic token.

Verified with RuboCop, 304 specs, 23 offline replays, the in-place column rename on a test project (all 45 cards kept their places), a dry-run sweep of RubyLLM on the real board, and a live evaluation of the default model: 20 of 23 cases. The three misses were an extra recap on a short feature request (one of two reruns), a missed duplicate (passed both reruns), and a correct closer-look judgment that took one model call over budget.
