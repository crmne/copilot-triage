Triage now catches what we caught by hand. We triaged Spotifast, ZapFast, RubyLLM, and TonePush ourselves, wrote down everything the bot missed, and taught it all of it: screenshots for interface changes, conflicts, stacks, failing checks, issues a release already fixed, and a recap of every long issue so you don't have to read it all.

## New

- **Screenshots for interface changes.** List the files that make up your interface in `pull_requests.visual_paths`. When a pull request changes one and neither its description nor its author's comments hold an image or video, triage asks for the evidence your contribution rules require. A change that plainly shows nothing, such as a logic fix, is left for you to waive instead. Spotifast [#1029](https://github.com/crmne/spotifast/pull/1029) and [#982](https://github.com/crmne/spotifast/pull/982) went through without anyone asking. By @crmne.
- **Pull requests that need more than a code review.** Triage asks for a rebase when a pull request conflicts with its base branch, naming the files both sides changed. It sends back pull requests whose checks fail, tells you when no checks ran, gives the merge order of stacked pull requests, and names open pull requests that change the same files or supersede each other. It also asks to leave out regenerated translation catalogs and unrelated lockfile changes, to split pull requests that bundle unrelated changes, and checks whether the default branch already does what a new feature adds. By @crmne.
- **Your decisions stay yours.** Redesigns, new settings, new public API, and approximations of capabilities your project says it lacks go to Decide, never Sign off, whatever the review bots concluded. Cosmetic details of a change whose screenshots are complete are optional follow-ups, not a reason to send it back. By @crmne.
- **A recap of every long issue.** A newly opened issue of at least 100 words, not counting logs and code, gets a short recap that leads with the fact that settles it, in plain words, so you don't have to read the whole report. Before, it took 2,000 characters and no template headings. By @crmne.
- **Settle what a release fixed.** A new Settle workflow runs when you publish a release, or by hand for a tag. It finds the open issues that the release's pull requests close or mention, and those its notes mention, and assesses each against the release. ZapFast had 18 open issues that 0.20 had already fixed. See [After a release](https://github.com/crmne/copilot-triage#after-a-release) for the workflow to add. By @crmne.
- **Issues link the pull request that may fix them.** An issue's report lists the open and recently merged pull requests that reference it. Triage links a likely fix, and asks the reporter to try a build from the default branch once it has merged. By @crmne.
- **needs-info comes off.** When the reporter supplies what a label like `needs-info` asked for, triage removes it. Only labels your policy lists, and only after the reporter spoke last. By @crmne.
- **Better answers from your own documents.** Triage cites the project's own rules in AGENTS.md or CONTRIBUTING.md when one answers a report. It points to the name your project already uses for a concept, such as `instructions` rather than `system_prompt`, and names an existing mechanism that nearly does what a request asks. It also says when code breaks a promise the docs make, and where a fix belongs when the cause is in a dependency. It never argues that a request is too niche. By @crmne.
- **Reporters on an old version.** When the latest release fixed the problem, triage names that release and asks the reporter to update. By @crmne.
- **Quiet issues come back to you.** An issue waiting on someone else after your reply moves to Decide after 21 quiet days, with a next step to nudge or mark it up for grabs. TonePush [#8](https://github.com/crmne/tonepush/issues/8) waited two months for a pull request you had approved. By @crmne.

## Fixed

- **A run that ends without a decision gets one more try.** ZapFast [#550](https://github.com/crmne/zapfast/issues/550) got no assessment because the fallback model answered even the forced reminder in plain text. That failure alone is now retried once with a fresh conversation, on either engine. By @crmne.
- **A declined idea is not a closed case.** A new report of something once declined is linked as related and left to you, unless your documents rule it out, since decisions change. By @crmne.

Verified with RuboCop, 471 specs, the 34-case offline reply evaluation, and the live reply evaluation on `openai/gpt-5.6-luna` through OpenRouter, the fallback model, which passed 33 of 34 cases. The miss is a recap that said "one full core" where the case wants "90%", which v0.18.0 misses just as often. The new pull request facts, the needs-info removal, and the Settle workflow were tested against recorded GitHub responses, not tried end to end.

## Known limitations

- Triage does not view images, so it cannot judge what screenshots show, only whether they are there.
- A pull request that fixes an issue without referencing it, such as TonePush [#31](https://github.com/crmne/tonepush/pull/31) for [#44](https://github.com/crmne/tonepush/issues/44), is not linked: triage only follows references.
- Conflicting files are those both sides changed since they diverged, not GitHub's exact conflict list.
- The Settle workflow has not run against a real release yet. A release published by a workflow's own token starts no other workflow, so run Settle by hand for that tag.
