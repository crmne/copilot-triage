## New

- **Columns sorted by what each item takes.** Approve (a quick yes), Answer or decide, Review (focus time), and Fix (your work), then Waiting on others and Backlog. Clear Approve in minutes and save Review and Fix for later. The agent now picks the next move for every issue and pull request. By @crmne.
- **Pull requests follow Copilot's verdict.** "Approval recommended" goes to Approve, "Changes recommended" back to the author, and a pull request whose review or checks are still running waits, including right after a push. "Needs a closer look" is the agent's call: ready for you when Copilot only flags a broad or risky change, back to the author when Copilot names something still wrong. Triage runs when Copilot's review arrives; the daily sweep sends forks' pull requests, once per review. By @crmne.
- **Your review, requested where it matters.** While a pull request sits in Approve or Review, your review is requested, so GitHub's review-requested list is your queue. It is withdrawn when the card moves on. Set `board.maintainer`. By @crmne.
- **The board builds itself.** Point the policy at an empty project and run the sweep once: it creates the columns in order, the Priority and Next step fields, an All repositories view, and a view per repository once it has cards, and keeps that shape on every run. By @crmne.
- **Finished work leaves the board.** Closed issues and closed or merged pull requests are archived, still searchable in the project, instead of piling up in a Done column. By @crmne.
- **Consistent labels.** Triage creates any label from your policy that a repository lacks, so issues and pull requests get the same labels everywhere. By @crmne.
- **Closer-look evaluations.** Eight real pull requests whose last verdict was "needs a closer look", four merged and four closed, check that the agent judges them the way the maintainer did. By @crmne.

## Changes for existing workflows

Workflows on `crmne/copilot-triage@v0` receive this release automatically.

- **The board's columns change.** On the next sweep, the columns of v0.7 (Needs me, Waiting on them, Blocked, Ready to merge, In progress, Done) are replaced and their cards placed again; a column of your own survives. If you named columns in `board.columns`, use the new keys: `approve`, `decide`, `review`, `fix`, `waiting`, `backlog`.
- **Copilot reviews need a trigger.** Add `pull_request_review: types: [submitted]` to the triage workflow and allow it in the job's condition; see the README. For forks, give the sweep `triage-workflow` and the triage workflow a `workflow_dispatch` trigger.
- **`board.maintainer`** replaces `assign_urgent_to`, which still works.

## Known limitations

- A large pull request can still run out of the 90-second budget while the agent judges a closer look; that run changes nothing, and the card stays where the sweep put it.
- GitHub's API cannot set a view's sorting or grouping beyond the board's columns; sort a view by Priority in the project if you want it.
- Fine-grained tokens cannot reach user-owned projects yet, so the board needs a classic token.

Verified with RuboCop, 286 specs, 23 offline replays, a live sweep that migrated a test project from the v0.7 columns, and live evaluations of the default model: 15 of 16 closer-look judgments across two rounds, and 14 of 15 issue cases.
